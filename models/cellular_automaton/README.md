# セルオートマトン

セルを格子上に並べ、近傍の状態から全セルを同時に更新する計算モデル。
一次元・2状態・半径1のセルオートマトンと、二次元のライフゲームを実装する。

| モデル | registry 名 | Code | AInput |
| --- | --- | --- | --- |
| 一次元 | `cellular_automaton` | ルール番号 `0..255` | 一行のセル列 |
| ライフゲーム | `game_of_life` | 空文字列 | 改行で区切った長方形の盤面 |

セルは `0` / `1`、または `.` / `#` で指定する。`1` と `#` が生きたセル。
入力は空にできず、行の途中に空白は入れない。出力は `0` / `1` に統一する。
入力の外側は初期状態ではすべて 0。格子は無限に広がり、端の折り返しはない。

RInput は空文字列。一段階で一世代進み、ROutput に次世代のセル列・盤面を返す。
静止・消滅・周期的なパターンでも自動停止しない。FOutput は使用しない。
毎世代、保持する領域を各方向に一セルずつ広げるため、長時間の実行ではメモリ使用量が増える。
描画は現在の世代の `■` / `□` の表。履歴は状態に蓄積しない。
snapshot の保存・復元に対応し、復元時にはルール番号、盤面の形、世代数を検証する。

## 一次元

左・中央・右の値を `l, c, r` とすると、次の値はルール番号の
`4*l + 2*c + r` 番目のビット（最下位ビットが0番目）。
例えば Rule 30 は次の更新表になる。

| 近傍 | 111 | 110 | 101 | 100 | 011 | 010 | 001 | 000 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 次の値 | 0 | 0 | 0 | 1 | 1 | 1 | 1 | 0 |

初期入力の左端を座標0とする。世代 `g` の表示領域の左端は `-g`。
表示領域の外側の一様な値は `background` に保持し、同じルールで更新する。
これにより、Rule 1 のように無限遠が世代ごとに反転する場合も扱える。

<div data-model="cellular_automaton">
<template data-default-code>
30
</template>
<template data-default-ainput>
1
</template>
</div>

`1 → 111 → 11001 → 1101111` と進む。Code を `110` などに変えると別のルールを試せる。

```sh
opam exec -- dune exec repl-machine -- model cellular_automaton --code 30 --ainput 1
```

## ライフゲーム

Conway のライフゲーム（B3/S23）。周囲8セルのうち、生きたセルが3個なら誕生し、
生きたセルは隣接する生きたセルが2個または3個のとき生存する。それ以外は死ぬ。
更新中の値を隣のセルの計算に使わず、全セルを同時に更新する。

初期入力の左上を `(0, 0)` とし、右が x の正方向、下が y の正方向。
世代 `g` の表示領域の左上は `(-g, -g)`。表示領域の外側は常に死んでいる。

グライダーは4世代で右下へ一セル移動する。

<div data-model="game_of_life">
<template data-default-code></template>
<template data-default-ainput>
.#.
..#
###
</template>
</div>

横一列の3セル（ブリンカー）は縦一列と横一列を交互に繰り返す。
最初の入力が一行でも、上下の領域へ広がる。

```sh
opam exec -- dune exec repl-machine -- model game_of_life --code '' --ainput '###'
```

どちらも空行を入力すると一世代進み、`:snapshot` で保存状態、`:quit` で終了する。
