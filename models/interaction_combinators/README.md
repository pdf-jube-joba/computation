# Interaction Combinators

主ポート同士がつながった2ノードを、局所的な規則で書き換える計算モデル。
[Yves Lafont, *Interaction Combinators* (1997)](https://doi.org/10.1006/inco.1997.2643)
の §2.1・Fig. 2 にある3記号・6規則を実装する。
ノードを置く位置は意味を持たず、ポートの番号と接続だけが計算を決める。

| 記号 | 宣言 | 主ポート | 補助ポート |
| --- | --- | --- | --- |
| γ | `\gamma a;` | `a.0` | `a.1`, `a.2` |
| δ | `\delta a;` | `a.0` | `a.1`, `a.2` |
| ε | `\epsilon a;` | `a.0` | なし |

番号は原論文と同じく主ポート0から時計回り。γ と δ の補助ポートは区別する。

## ネットの記法

Code にノード宣言と配線を書く。AInput は空文字列。

```text
\gamma a;
\gamma b;
a.0 ~ b.0;
a.1 ~ @x;
a.2 ~ @y;
b.1 ~ @u;
b.2 ~ @v;
```

`a.1 ~ b.2;` は無向の配線。`@x` はネットの外部ポートを表す。
宣言と配線の順序は自由だが、各文の末尾の `;` は必須。
全ノードの各ポートと、記述した各外部ポートは、必ず一度だけ配線に現れる。
同じノードの異なるポートをつなぐことも、外部ポート同士をつなぐこともできる。
未接続・重複接続・未宣言ノード・存在しないポートはエラー。

ノードに接しない閉じたワイヤは `\loops 2;` のように個数で表す。
省略時は0本。空の Code は空ネットで、即座に停止する。
切り離された成分も保持し、閉じたワイヤを勝手に削除しない。

## 6規則

以下の `a` と `b` は、主ポート `a.0 ~ b.0` で接続されたノード。
表の接続先は、元の補助ポートに接していた配線の先を意味する。

| 組 | 書き換え |
| --- | --- |
| γ–γ | 2ノードを消し、`a.1 ↔ b.2` と `a.2 ↔ b.1` をつなぐ |
| δ–δ | 2ノードを消し、`a.1 ↔ b.1` と `a.2 ↔ b.2` をつなぐ |
| ε–ε | 2ノードと主ポート間のワイヤを消す |
| γ–ε | 2ノードを消し、γ の各補助ポートの先に新しい ε を付ける |
| δ–ε | 2ノードを消し、δ の各補助ポートの先に新しい ε を付ける |
| γ–δ | 2ノードを消し、γ を2個、δ を2個作って下記のようにつなぐ |

γ–δ では元の γ の補助ポート `i` の先に新しい δ `d_i` の主ポートを、
元の δ の補助ポート `j` の先に新しい γ `g_j` の主ポートを付ける。
内部では `d_i.j ~ g_j.i`（`i,j ∈ {1,2}`）の4本をつなぐ。
生成ノードには衝突しない `n0`, `n1`, … という名前を付ける。

γ–γ と δ–δ の接続は異なる。片方をもう片方と同じ規則に置き換えない。
元の補助ポート同士が直接つながっていても書き換えられ、その結果できた輪は
`loops` の個数に加算する。

## 一段階ずつ動かす

モデル名は `interaction_combinators`。RInput が空なら、ノード名の辞書順で
最初の active pair（主ポート同士の接続）を一組だけ簡約する。
`a b` を入力すればその組を選べる。`b a` でもよい。
存在しない組や active pair でない組の指定はエラーになり、状態は変わらない。

ROutput は適用した規則名（例：`gamma-delta`）。active pair がなくなった次の step で
停止し、FOutput に残ったネットを Code と同じ形式で返す。出力のノードと配線は整列する。
主ポートから補助ポートへつながるサイクルや、閉じたワイヤが残っていても、
active pair がなければ停止する。一般のネットの計算は停止するとは限らない。

描画は接続図・次に簡約する組・active pair 一覧・配線表・閉じたワイヤの個数。
図の赤い辺は、空の RInput で次に選ぶ主ポート間の接続。
ポート0は大きな点で表示する。ノード ID とポート番号は配線表でも確認できる。
snapshot はネットと簡約回数を保存し、復元時にも配線の整合性を検査する。

### γ–γ の消去

<div data-model="interaction_combinators">
<template data-default-code>
\gamma a;
\gamma b;
a.0 ~ b.0;
a.1 ~ @x;
a.2 ~ @y;
b.1 ~ @u;
b.2 ~ @v;
</template>
</div>

一度簡約すると、`@x ~ @v;` と `@y ~ @u;` の配線が残る。

### 木を複製する

δ に、ε を2枚の葉とする γ の木をつなぐ。
最初の γ–δ で複製を始め、その後の2回の δ–ε で葉を複製する。
3回の簡約で、`@left` と `@right` に同じ形の木が1本ずつできる。

<div data-model="interaction_combinators">
<template data-default-code>
\delta dup;
\gamma pair;
\epsilon l;
\epsilon r;
dup.0 ~ pair.0;
dup.1 ~ @left;
dup.2 ~ @right;
pair.1 ~ l.0;
pair.2 ~ r.0;
</template>
</div>

CLI から消去を試す例：

```sh
opam exec -- dune exec repl-machine -- model interaction_combinators \
  --code '\epsilon a; \epsilon b; a.0 ~ b.0;' --ainput ''
```

空行で一段階進む。`:snapshot` で状態を確認でき、`:quit` で終了する。

## 検証

6規則の端点対応、内部配線から生じる輪、消去の連鎖、木の複製、
独立な簡約の順序交換、codec と snapshot の往復をテストする。
さらに原論文 §3.1 の2スタックによる経路の意味論を独立に実装し、
各規則の前後で外部ポート間の経路が一致することを確かめる。
Web 用の共通 renderer にポート付き無向グラフを追加し、既存の描画形式と併用する。
