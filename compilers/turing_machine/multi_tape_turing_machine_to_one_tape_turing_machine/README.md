# 多テープから1テープへの変換

`multi_tape_turing_machine-one_tape_turing_machine` は
[多テープ機械](../../../models/turing_machine/multi_tape_turing_machine/README.md)のコードから
[1テープ機械](../../../models/turing_machine/one_tape_turing_machine/README.md)の遷移表を生成する。
生成コードは通常の1テープモデルで実行できる。

## テープの符号化

各テープの初期ヘッド位置を座標0とし、同じ座標のセルをテープ順に並べて1列にする。
1列は `k` 個のセルからなり、それを座標順に並べて左右を `mt_left`・`mt_right` で囲む。
各セルにはテープ番号、ヘッドの有無、元の記号を識別子として格納する。
たとえば `mt0_h_Sa` は第1テープのヘッド上の `a`、`mt1_p_B` は第2テープのヘッド外の空白。
元の記号も接頭辞を付けて符号化するため、これらと同名の入力記号も使える。

## 遷移の生成

シミュレートする状態ごとに、元の遷移を順に調べる。

1. テープを走査し、各ヘッド位置の記号が遷移の読み取り記号列と一致するか確認する。
2. 全記号が一致したら、左右に空白の列を1列ずつ追加する。
3. 各ヘッド位置を書き換え、移動方向に応じて1テープのヘッドを `k` セル移動し、新しいヘッド位置を記録する。
4. 左端に戻り、次状態の処理を開始する。

読み取り記号列全体を確認してから書き換えるので、多テープ版の同時読み書きを保つ。
受理状態には遷移を生成せず、どの遷移も一致しない場合も左端に戻って停止する。
左右への拡張により、初期入力の範囲を超えるヘッド移動も扱える。
固定した元の機械について、1ステップの模倣には使用領域の長さに比例した走査が必要になる。

## API

- `compile`: 型付きコードから1テープの型付きコードを生成する。
- `encode_ainput`: 全入力テープを1本に符号化する。
- `decode_foutput`: 停止時の1本のテープから、元の各テープとヘッド位置を復元する。
- `api`: CLI / Web 用のテキスト API。

入力は元のコードのテープ本数・アルファベットに従う。
入力の符号化 API はコードを受け取らないため、この対応関係の検査は元モデルの `make` が行う。
復号時は、拡張によって増えた両端の空白を取り除く。ヘッド位置と非空白セルの相対位置は保たれるが、
明示的な末尾空白の個数は元モデルのテキスト出力と異なることがある。
比較には無限の空白を同一視する `Tape.equal` を使える。
